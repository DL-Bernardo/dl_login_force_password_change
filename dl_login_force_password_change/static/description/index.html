❓ Frequently Asked Questions (FAQ)

Clear, direct answers to common administrative, architectural, and security questions.

Can users bypass the password reset screen by typing another URL in the browser?

No. The module hooks directly into Odoo's core ir.http routing lifecycle. If a user has the force password flag active, any attempt to navigate to any backend URL (e.g. /web or /web#action=...) is immediately intercepted and redirected back to the secure password update portal.

Is this module compatible with Odoo.sh and multi-company environments?

Yes, 100%. The module has been thoroughly verified on Odoo.sh, self-hosted Ubuntu VMs, and containerized Docker setups. It respects company-level user boundaries and operates seamlessly in multi-company environments.

Can an administrator adjust or disable the 11-month expiration policy?

Yes. The expiration rule is powered by a standard Odoo Scheduled Action (ir.cron). You can customize its schedule or configure the system parameter dl_login_force_password_change.expiration_days to any desired interval (e.g., 90, 180, or 365 days), or simply disable the cron job if periodic expiration is not desired.

What password complexity rules are verified in real time?

The built-in engine checks four essential security criteria: (1) Minimum length of 8 characters, (2) At least one uppercase letter, (3) At least one digit or special symbol, and (4) Exact match between the new password and confirmation field.

Does installing this module force all existing users to change passwords immediately?

No. Existing users will not be prompted unless an administrator explicitly activates "Force Password Change on Next Login" on their card, or if their last change date exceeds the configured periodic expiration threshold. Newly created internal users are flagged automatically on account creation.
